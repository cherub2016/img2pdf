# 🖼️ img2pdf.py  
### 高性能影像归档工具（v0.47）- EXIF 方向校正 + OCR 方向检测 + 压缩包自动解压 + PDF/A 支持

---

## 📘 项目简介

`img2pdf.py` 是一款基于 Python 的命令行工具，可将指定文件夹及其子文件夹内的图片（`.jpg` / `.jpeg` / `.png` / `.bmp` / `.tiff` / `.tif`）自动转换为 **A4 PDF 文件**。

支持：
- 自动递归扫描目录；
- **自动解压压缩包（ZIP）到同名文件夹**；
- 每个文件夹生成一个 PDF；
- **智能跳过已存在的PDF文件**，支持增量处理；
- **PDF生成成功后可选删除原压缩包**；
- **EXIF 方向优先**（使用现代 Pillow API），OCR 方向检测作为兜底；
- 自动选择横向或竖向 A4 页面；
- **横向页面自动添加边距**，提升美观度；
- **禁止小图片放大**，保持清晰度；
- 图片 **等比缩放、居中显示**；
- 命令行彩色日志提示；
- 支持集中输出所有 PDF 文件到指定目录；
- 可选转换为合规的 **PDF/A-1b** 格式；
- **运行时间统计**，提供详细的性能分析；
- **改进的资源管理**，确保内存和临时文件正确释放；
- **增强的安全验证**，防止路径遍历和 Zip Bomb 攻击。

   - Windows: [Ghostscript 官网](https://www.ghostscript.com/releases/gsdnld.html)
   - Linux: `sudo apt install ghostscript`
   - macOS: `brew install ghostscript`

## 🚀 使用方法

### 查看帮助信息
```bash
python img2pdf.py -h
```

输出示例：
```
高性能图片转 A4 PDF（EXIF+OCR方向检测，支持PDF/A）

用法：
  python img2pdf.py <源目录> [输出目录] [选项]

参数说明：
  源目录              必填，包含图片文件或压缩包的主文件夹
  输出目录            可选，若省略则 PDF 保存在源目录对应文件夹中
  
选项：
  --extract          自动解压源目录中的压缩包（ZIP）到同名文件夹
  --delete-archive   PDF生成成功后删除原压缩包（需配合 --extract 使用）
  --keep-structure   保持源目录结构输出PDF（默认为扁平化输出）
  --pdfa            生成符合 PDF/A-1b 标准的文档（需要 Ghostscript）
```

---

### 📁 示例一：基本用法（PDF 保存在源目录）
```bash
python img2pdf.py "D:\扫描文件"
```
程序行为：
- 递归扫描 `扫描文件` 目录及其所有子文件夹；
- 每个含图片的文件夹生成一个独立 PDF；
- 生成的 PDF 与图片位于同一目录；
- 文件命名格式：`<目录名>.pdf`。

---

### 📁 示例二：压缩包自动处理
```bash
python img2pdf.py "D:\压缩包目录" "D:\PDF输出" --extract --delete-archive
```
程序行为：
- **阶段1：解压**
  - 扫描所有 `.zip` 压缩包
  - 解压到同名文件夹（如 `报销单.zip` → `报销单/`）
  - 如文件夹已存在则跳过解压
- **阶段2：生成PDF**
  - 处理解压后的文件夹，生成 PDF
  - PDF 保存到指定输出目录
- **阶段3：清理**
  - PDF 生成成功后，自动删除对应的压缩包
  - 验证 PDF 有效性后才删除，确保数据安全

💡 **典型场景**：
- 📧 客户发送的压缩包批量归档
- 💼 事务所影像资料标准化处理
- 🔄 自动化工作流，无需手动解压

---

### 📁 示例四：PDF 集中输出（支持增量处理）
```bash
python img2pdf.py "D:\扫描文件" "D:\PDF输出"
```
程序行为：
- 扫描源目录及子目录中的所有图片；
- 每个子文件夹生成一个独立 PDF；
- **所有 PDF 文件统一保存到指定目录**；
- **自动跳过已存在的同名PDF文件**，仅处理新增或未处理的文件夹；
- 若文件被占用时保留临时文件。

💡 **增量处理优势**：
- ⏱️ 节省时间：避免重复处理已完成的文件夹
- 🔄 断点续传：可随时中断，下次继续处理未完成部分
- 💾 资源高效：仅处理新增内容，减少系统负载

---

### 📁 示例四：生成 PDF/A 文档
```bash
python img2pdf.py "D:\扫描文件" "D:\PDF输出" --pdfa
```
程序行为：
- 除了基本的 PDF 生成外；
- 使用 Ghostscript 将生成的 PDF 转换为 PDF/A-1b；
- 确保长期保存的文档合规性。

---

### 📁 示例六：仅解压压缩包（不生成PDF）
```bash
# 如果只需要解压，可以先运行解压，然后根据需要再生成PDF
python img2pdf.py "D:\压缩包目录" --extract
```

## 🧠 智能处理逻辑

### 1️⃣ 方向校正（两级策略）
- **第一级**：EXIF 方向信息（现代 API）
  - 使用 Pillow 最新 `getexif()` API（替代已弃用的 `_getexif()`）
  - 直接通过 `0x0112` 标签获取 Orientation 信息
  - 根据标签值自动旋转（0°/90°/180°/270°）
  - 提高向前兼容性
- **第二级**：OCR 方向检测（兜底）
  - 当 EXIF 信息不存在或无效时启用
  - 使用 Tesseract OCR 分析文字方向
  - 支持检测 0°/90°/180°/270°
  - 自动转换图像格式以提高 OCR 准确性
  - 检测失败时保持原始方向

### 2️⃣ 页面布局自适应
- 基于图片比例自动选择页面方向：
  - 宽 > 高：使用横向 A4
  - 高 ≥ 宽：使用竖向 A4
- 自动计算最佳缩放比例
- 居中放置，确保美观

### 3️⃣ 并行处理策略
- 自动检测 CPU 核心数（最多使用 8 个）
- 多进程并行处理不同目录
- 每个子进程独立处理一个目录的图片

### 4️⃣ 智能跳过机制
- 处理前检查目标PDF文件是否已存在
- 已存在则自动跳过该文件夹，避免重复处理
- 提供清晰的日志区分"跳过"与"完成"状态
- 支持增量处理和断点续传

## ⚠️ 注意事项

1. **运行环境**
   - 确保 Python 3.8+ 环境
   - 安装必要的 Python 包
   - OCR 检测需要 Tesseract
   - PDF/A 转换需要 Ghostscript

2. **压缩包处理**
   - 当前仅支持 ZIP 格式（未来可扩展 RAR、7Z）
   - 如文件夹已存在则跳过解压
   - 删除压缩包前会验证 PDF 有效性
   - 建议先测试少量文件，确认无误后批量处理

3. **输入/输出**
   - 支持 .jpg/.jpeg/.png/.bmp/.tiff/.tif 格式图片
   - 确保源目录读取权限
   - 确保目标目录写入权限
   - 不要打开正在生成的 PDF

4. **资源使用**
   - 并行处理会占用较多内存
   - 建议预留足够磁盘空间（解压+PDF）
   - PDF/A 转换需要额外处理时间

5. **错误处理**
   - 单个图片错误不影响整体处理
   - 文件占用时会保留临时文件
   - 详细日志帮助定位问题
   - 压缩包解压失败不影响其他处理

6. **智能跳过**
   - 已存在的PDF不会被覆盖
   - 如需重新生成，请先删除目标PDF文件
   - 跳过逻辑基于文件名匹配

## 🔒 安全特性

- ✅ **路径规范化**：使用 `os.path.abspath()` 防止路径遍历攻击
- ✅ **Zip Bomb 防护**：检测解压后文件大小，限制10GB上限
- ✅ **路径遍历检查**：验证压缩包内文件路径安全性
- ✅ **文件验证**：处理前验证输入文件存在性和可读性
- ✅ **权限检查**：自动检查源目录读取权限和输出目录写入权限
- ✅ **安全命令执行**：Ghostscript 调用使用列表参数，避免命令注入
- ✅ **PDF 验证**：删除压缩包前验证 PDF 文件有效性
- ✅ **资源隔离**：多进程环境下每个任务独立运行，互不影响
